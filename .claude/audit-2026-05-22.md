# Kerf Codebase Audit — 2026-05-22

Three-specialist sweep: Razor (code efficiency), Jen (UX flow), Research (competitive UX patterns).

## Tier 1: Core Loop Performance (Razor)

The drag/pan/move interaction — used hundreds of times per session — triggers cascading Zustand updates that cause full Pixi re-renders. This is the single biggest performance bottleneck.

| #      | Finding                                                                                  | Impact                                             | Fix                                                        |
| ------ | ---------------------------------------------------------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------- |
| **P1** | N Zustand `set()` calls per pointer-move during drag (one per selected object)           | 600 state updates/sec with 10 objects at 60fps     | Batch into single `updateObjects()` action                 |
| **P2** | `setGuides()` fires unconditionally every pointer-move, even when guides haven't changed | React reconciliation every frame                   | Diff before write, or move guides out of Zustand entirely  |
| **P3** | All Pixi display objects re-render on any single object change                           | 100+ Graphics clears per frame during drag         | Track dirty set, only re-render changed objects            |
| **P4** | `setCursorPosition` triggers full Zustand notify at 60fps                                | StatusBar re-renders 60x/sec                       | Move cursor position out of Zustand into a ref             |
| **P5** | Pan writes `setCamera` to Zustand every pointer-move                                     | Entire viewport re-renders during pan              | Update Pixi world directly, sync to store on pointer-up    |
| **P6** | `objects.find(id)` O(n) called per-selected-object per-frame                             | O(n\*k) per frame (n=objects, k=selected)          | Maintain `objectsById: Map<string, DesignObject>` in store |
| **P7** | Selection overlay effect re-runs on every `objects` change                               | Handles/bbox redrawn when unrelated objects change | Subscribe to `selectedObjects` slice with shallow equality |
| **P8** | Text/Image Pixi objects destroyed + rebuilt on every unrelated update                    | GPU texture upload per text object per frame       | Content hash check, skip if unchanged                      |

**Estimated combined impact**: These 8 fixes would transform the drag/pan experience from "gets sluggish with 50+ objects" to "smooth at 500+". P1-P3 alone cover ~80% of the improvement.

## Tier 3: Competitive Polish (Research)

From laser cutter community analysis — what makes the difference between "works" and "feels professional."

| #       | Finding                                                                      | Frequency cited | Recommendation                                                                               |
| ------- | ---------------------------------------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------- |
| **R1**  | Material presets accessible from layer panel (one-click apply)               | Highest         | Searchable dropdown on each layer row, not buried in MaterialLibrary panel                   |
| **R2**  | Connection state in primary chrome (color-coded, persistent, human-readable) | Very high       | Map GRBL states to labels: Ready/Running/Paused/Error/Homing. Color-coded dot in status bar. |
| **R3**  | Frame button as first-class affordance (trace job bounding box on machine)   | Very high       | Promote Frame to primary button adjacent to Start, not buried in action row                  |
| **R4**  | SVG import post-import report ("47 paths, 3 open, 1 text converted")         | High            | Toast/banner after every import showing what happened                                        |
| **R5**  | Origin indicator on canvas (visual, adjustable job start point)              | High            | Draw origin crosshair on canvas, "set to current position" button                            |
| **R6**  | Keyboard shortcut for layer assignment (1-6 number keys)                     | High            | Number keys assign selected objects to layer N                                               |
| **R7**  | Job progress: percentage + elapsed + estimated remaining                     | High            | Already have progress bar; add time display                                                  |
| **R8**  | First-run: connect → home → ready in under 5 clicks                          | High            | Guided wizard: detect ports, confirm GRBL handshake, home, done                              |
| **R9**  | Actionable error messages on connection failure                              | High            | Suggest: check COM port, verify baud rate, confirm firmware                                  |
| **R10** | Undo depth 50+ including layer/settings changes                              | Table stakes    | Already have 50-step undo — verify settings changes are captured                             |

## Tier 4: Code Health (Razor)

Lower urgency but prevent future problems.

| #       | Finding                                                                    | Fix                                               |
| ------- | -------------------------------------------------------------------------- | ------------------------------------------------- |
| **C1**  | `dialogState` is a module-level mutable object with stale-closure risk     | Replace with Zustand modal state or event emitter |
| **C2**  | Double `setTimeout` hack for Fill+Line sub-layer creation                  | Add `addTwoSubLayers()` atomic action             |
| **C3**  | `getState()` in App render body loses reactive updates for PdfImportDialog | Subscribe properly via `useStore` hook            |
| **C4**  | Synchronous `generate_gcode` blocks Tauri main thread                      | Convert to async with `spawn_blocking`            |
| **C5**  | `PX_PER_MM` magic number duplicated in 5 files                             | Extract to `src/lib/constants.ts`                 |
| **C6**  | Inconsistent ID generation (`generateId()` vs `Date.now()+random`)         | Use `generateId()` everywhere                     |
| **C7**  | Rotation modulo doesn't normalize negatives                                | `((r % 360) + 360) % 360`                         |
| **C8**  | `offsetRingByDistance` duplicated in gcodeGen.ts and geometryActions.ts    | Extract to shared `src/lib/geometry.ts`           |
| **C9**  | `Array.includes` on `selectedIds` in O(n) loops                            | Expose `selectedSet: Set<string>` from store      |
| **C10** | O(n²) time estimate in JS G-code fallback                                  | Use loop index instead of `indexOf`               |

## Recommended Execution Order

**Sprint 1 — Core Loop Performance** (Tier 1: P1-P8)
Highest impact per line of code changed. Fixes the drag/pan/render pipeline. ~15 files, mostly toolHandler.ts, Viewport.tsx, store/index.ts. Pure refactoring — no new features, no UI changes, no Rust changes. Testable by "does it feel faster with 100+ objects?"

**Sprint 2 — UX Bug Fixes** (Tier 2: U1-U16)
Quick wins that fix actual bugs and close friction gaps. Most are 1-10 line changes. U3 (MachinePanel layout) is the biggest structural change.

**Sprint 3 — Competitive Polish** (Tier 3: R1-R10)
The features that make Kerf feel professional. R1 (material presets), R2 (connection state), R6 (keyboard shortcuts) are highest leverage. R8 (first-run wizard) is a bigger build.

**Sprint 4 — Code Health** (Tier 4: C1-C10)
Maintenance and correctness. Can be done opportunistically alongside other work.
