## Verdicts

### Core

1. **Problem-fit: PASS.** `## Intent (grilled)` is present with a written skip line and cites the three rulings. The summary matches the parent §S3, `kerf-f1` (refuse, plain words, persist per machine) and Jen C3 verbatim. No DECISIONS conflict.
2. **Approach soundness: CONCERN.** Pure `clipJog` plus a precondition function is right, and D1 (one jog in flight) is the correct answer to the planned-versus-reported position gap. Two mechanics are wrong as written: (a) the pending clear keys on `accepted`, which is true for a busy poll that wrote no state, so a poll that began after the ack and hit a held command lock clears `jogPending` on the *stale* `"idle"` still in the store, while the head is moving; (b) the precondition list has no `jobRunning` check, and during a job the store reads idle and fresh (verified above), so the gate admits a jog mid-job. Fixes in the must-fix list.
3. **Completeness: CONCERN.** Three states are not covered: jog during a running job (above); reconnect with the previous session's `statusStale: false` and `positionKind` still set, which opens a short window where the bed is verified by memory but the position is last session's, and shows a green "Idle" until the first poll (this is Jen C3 recurring on every reconnect); an unrecognised axis (`jog("Z", …)`) is unspecified after "normalize to X|Y" and today is sent raw. Also the `positionKind === null` half of check 4 has no mutant.
4. **Right-sizing & reuse: PASS.** Reuses `canStartJob`'s shape, `useSyncExternalStore` (already the StatusBar pattern), S2's module and test. 12-file waiver is stated with reasons; the split is named and would change nothing. Every deferral is indexed to the Parking Lot at 3.5. The split would not have prevented any finding here, so I do not prefer it.
5. **Security: PASS.** localStorage JSON, try/catch on every access, malformed reads as absent, no eval, no network. A hostile localStorage entry can at worst set a wrong bed, which the operator sees on the panel.
6. **Failure modes: CONCERN.** `send()` returning `error:disconnected` or `error:8` clears pending (good); a poll rejected for old seq does not clear (good); the 3-strike path clears via `disconnect` (good). Missing: the busy-poll case (dimension 2) and the fact that `jogPending` survives a job start (a START within one poll of a jog ack is admitted by `canStartJob`, the first job line earns `error:9` during Jog, and the stream aborts with `0x18` mid-motion, ALARM:3, position lost). Beam is off in every path, so this is nuisance-class; advisory fix below.
7. **Change safety: PASS.** No irreversible step; revert order named; the only persistent write is one localStorage key an older build ignores.
8. **Data integrity & compatibility: CONCERN.** Single writer for the entry, controller always wins, read-on-lookup. Two drifts are named but only one is parked: `loadProject`/SettingsDialog resizing a verified bed (Parking Lot line 1, correct) and a console `$130=`/`$131=` write, after which `workspaceVerified` stays true against the pre-write size until reconnect (S1 W3 ruled no full parse on console `$$`). Add it to line 1, or clear `workspaceVerified` when a write targets `$130`/`$131` (one branch in the same invalidate hook S3 already edits). Also: the frame (`originTop`) is a *project* field (`store/index.ts:507`, `?? false`), the remembered bed is per *machine*; opening a pre-`originTop` project on the owner's machine flips the envelope to `[0, H]`. Pre-existing, outside S3, but worth one Parking Lot line because S3 makes the bed per-machine and leaves the frame per-project.
9. **Verifiability: PASS.** 25 mutants + 3 controls, each with a named test and a single-line anchor; anchors verified unique at HEAD; Ted re-counts on the finished tree. Property table ≥200 cases. Tests drive production functions only (copies forbidden). Two named test retirements with before/after in the report. One gap noted under 3 (positionKind-null half). Terminology: the plan's "control = killed" matches the battery; the parent's done_condition says "every control id green", which is a wording mismatch the coordinator should be told about, not a defect here.

- **X1 Physical & human safety: CONCERN.** Every refusal ends with nothing sent; the clip cannot reverse or grow (M2, M8); an out-of-envelope position refuses rather than clamps (M9); `jogTo` refuses rather than clamps (M3). - **X5 Concurrency & re-entrancy: CONCERN.** Double click: `jogPending` is set synchronously before the first `await`, so a second click in the same tick or any later tick is refused; race-free in a single-threaded runtime. Jog vs poll: the tick pair correctly rejects a poll that straddled either edge, and the ack-before-Jog-state ordering holds in stock GRBL (`jog_execute` sets `STATE_JOG` before the `ok` is reported), so a post-ack Idle proves completion; the fork is unverified, and hardware step 2 covers it. ## The six specific checks

1. **Persistence invalidation.** Sound. The seven invalidations cover a different controller on the same port in every case the controller can tell you about; a readback failure or a missing `$100/$101` yields no key; the controller's own travel always wins; disconnect clears the flag. A confirmation cannot be *re-applied* into a false state except the one the plan names: same port, same six settings, different physical frame. That residual is disclosed to the operator in two places (connect console line naming the size and "you confirmed this size earlier · Change" on the panel). It is acceptable: it is exactly today's in-session residual stretched across sessions, the OUTSIDE refusal catches a remembered bed that is too small, and a too-large one is bounded by hard limits on the owner's controller. It is not qualified on a `$21=0` machine and the plan should say that in one clause. One invalidation is *over*-broad, not under (X5, `$32=1`). One drift is under-covered (core 8, console `$130=` write).
2. **"One jog at a time".** Race-free for clicks and key repeat; two holes against the poll loop and the job loop, both fixable in one line each (must-fix 1, 2).
3. **Mutation ids.** Every claim checked and true (see Verified). S3-M20's find includes a comment; fragile against a comment edit but unique. S3-M23's IIFE replacement is valid TS and lints clean (`_ignored`).
4. **Stale indicator coverage.** Complete: MachinePanel header and StatusBar are the only two state-coloured surfaces; START's title already carries the stale reason. The reconnect window (must-fix 3) is the one case where "Stale" would not show when it should.
5. **"No build between S3 and S5".** The premise is correct: after S3, `jogTo` refuses `workspaceHeight - worldY` on an origin-top machine, so Position Laser is refused where today it drives past home. That is the safer state and a feature gap, not a hazard. It does **not** belong in S3's `done_condition` (which the parent already defines: branch ancestor, Razor PASS, battery journal). It is an **escalation** to the coordinator, and a build freeze is disproportionate: S5 waits on `refresh-editing-shortcuts`, which has not started (R2 is in flight), so the freeze would be open-ended. Options for the coordinator: (a) freeze, as the plan suggests; (b) allow builds with the refusal, but give the click a truthful reason (today's copy "That spot is outside the bed" is wrong for a click inside the drawn bed) and a ROADMAP `next` line; (c) let S3 take the one-line mapping in `handlePositionLaserDown` (`originTop ? -worldY : workspaceHeight - worldY`, the rule `gcode_gen.rs:421-427` already uses) as a 13th file, since R3 touches `toolHandler.ts` only to add `switchTool` and cannot conflict, and shrink S5 to its tests. I recommend (c), else (b). Either way the plan's Risks paragraph should say "escalated to the coordinator", not "no build".
6. **Hardware and serial.** No hardware claim is made; every physical assertion is under "Hardware-only"; every test file mocks `invoke`; the browser step is store-driven and says the memory path is unit-only. Holds.

## Stress tests

**Pre-mortem (three months out).**
1. *The head moved after a job.* An operator nudged a jog arrow while a buffered job ran; the gate said idle and fresh because nothing updates those fields during a job; the `$J=` queued behind the pump and executed when the job ended, beam off. We should have seen: the jog line in the console during the job. Prevented by must-fix 2.
2. *Two clicks, one overshoot.* A console command held the command lock for the poll after the ack; the busy poll cleared `jogPending` against the stale idle; the second click sent while the head was still moving, and both were clipped against the same position. We should have seen: two `$J=` lines within 250 ms. Prevented by must-fix 1.
3. *Green on reconnect.* The disconnect/reconnect hang Lee reported (ROADMAP Parking Lot) has him reconnecting often; each reconnect shows a green "Idle" for the length of the `$$` round trip with last session's position under it. Not a burn, but it is C3 again, and it undermines the trust the indicator is meant to earn. Prevented by must-fix 3.
Type-specific worst case: none of the three fires the beam. The worst physical outcome in this batch is a head-to-frame collision from a wrong remembered bed on a machine without hard limits; disclosed, and no worse than today.

**Load-bearing assumptions.**
- *A post-ack Idle proves the jog finished.* High confidence on stock GRBL (state set before `ok`); unverified on the CV fork. Consequence if wrong: D1 releases early and two clicks overshoot. Hardware step 2 is the check; keep it.
- *The store's `machineState`/`statusStale` are trustworthy when the poll loop runs.* True only when it runs; false during jobs (verified). Consequence: must-fix 2.
- *`$130/$131 > 0` on the owner's controller.* Verified from the capture (`$130=400`, `$131=415`); the memory path therefore never runs on his machine, which is why its only proof is unit tests. Consequence if his readback is ever truncated: the memory path runs cold on hardware. The plan already notes the "complete `$$`" hardware check from the parent.
- *S2 merges first with the module path as planned.* Unmerged; the plan's fallback (edit the dialog, 11 files) is stated. Resolve at Stage 0.

**Inversion.**
- *Absolute jogs (`$J=G90`) instead of one-at-a-time relative:* would win if the reported position were never more than one jog behind the planned one. It is not (250 ms poll, planner-relative `G91`), and a lagging position turns a queued absolute jog into a reversal. Rejection stands.
- *Key by port only:* would win if the OS never reused a port name for a different device. Linux does. Rejection stands.
- *No auto-apply, one click per session:* would win if `kerf-f1`(b) had not been ruled. It was. Rejection stands.
- *The split (S3a/S3b):* would win if the mirror and the jog work had different reviewers or a different merge window. They share a build and a Jen pass. Rejection stands.

## Overall verdict

CONCERN. The design is right: a pure clip that can only shrink toward zero, refusal over clamping everywhere the frame is unknown, one jog in flight, a per-machine memory that the controller always overrides and the operator can always see and change, and a full mirror that the label geometry actually needs. Every anchor, citation and sibling-plan claim checked true, and the plan never touches hardware or a serial byte. What it gets wrong are three gate mechanics that the tree contradicts: a busy poll counts as accepted, the store says idle and fresh for the whole of a job, and disconnect leaves last session's freshness behind. Each is one or two lines in files the plan already edits, each gets a mutant, and none changes the design. Fold them and this is a PASS.
