## Intent

Polish means the charter's five-step loop (Import, Trace if raster, Assign to layers, Preview, Send) reads truthfully at every step, in one visual system in the house style (dark, minimal chrome, Apple-like restraint). For Track A that is concrete: every string meets the contrast floor on the surface it actually sits on; one type scale; one colour meaning per colour; one dialog shell; every refusal Kerf already computes is visible where the eye is; STOP is never drawn dimmed while it can act; a layer that will not reach the G-code looks like it; and every word on screen says only what the code does or what the controller reported.

Grill: not run (written skip). The intent comes from Lee's request ("have a few UI critics run on opus extra high and come up with a plan for polishing") and the charter. The look-and-feel calls a grill would surface are under Decisions for Lee.

### The two tracks

**Track A, "UI polish, presentation only".** An item is in Track A only if all of these hold:
- it changes nothing that reaches the machine, and no import, trace or generation path;
- it changes no default that affects what burns (layer choice, preset values, curve points, units);
- it makes no claim about physical machine behaviour beyond facts the code or the controller's own report already establishes;
- it owns no asynchronous or stateful behaviour (timers, results, stop outcomes, regeneration, store writes);
- it does not change STOP reachability or any handler.

Typical Track A: tokens and type scale, contrast, spacing, the shared dialog shell, icons and label consistency, focus-visible styling, layout at 1280x800, empty states, copy that does not describe machine physics, and presentation-only styling of existing state. STOP's opacity and cursor keyed to its real `disabled` condition is presentation. Raising STOP above modals is not; that is TB1.

## Design principles (resolved)

### 1. Tokens and the contrast floor

Text is at least 4.5:1 on the surface it actually sits on, composited (alpha tints are blended over the panel, and no meaningful text carries `opacity` below 1). Control boundaries and focus rings are at least 3:1. Disabled controls are exempt (WCAG 1.4.3) and use `--text-disabled` or `opacity: 0.4`; nothing that is still clickable is drawn that way. ### 2. One type scale, a closed list for 10 px

- `--text-2xs` 10px is allowed for exactly three uses: caps section labels (uppercase, 600, letter-spacing 0.4px); text inside a badge or chip that has its own fill or border (FILL, LINE, OFFSET, FILL+LINE, OFF, IMG); canvas ruler numbers and the ruler's corner unit. Nothing else.
- `--text-xs` 11px is the floor for every other string.
- `--text-sm` 12px: values read at a glance (the machine state word in the status bar and Machine header, the position readout, the layer-strip values).
- `--text-md` 13px: body text, dialog buttons, the job progress line (600), STOP (700).
- `--text-lg` 14px: dialog titles. `--text-xl` 18px: the onboarding title. Any 16px text becomes 14px.
- No 7, 8 or 9 px anywhere after Track A. Every file with a sub-10px size is in a batch: MachinePanel 16 sites (A12), LayerPanel 16 (A6), PowerCurveEditor 6 (A4), Rulers 3 (A9), DitherPreviewDialog 3 (A4), PropertiesPanel 2 (A2), ImageTraceDialog 2 (A5), StatusBar 2 (A8), CommandPalette 1 (A10), PdfImportDialog 1 (A4), MaterialLibrary 1 (A2), ImageImportDialog 1 (A5), GrblSettingsDialog 1 (A11), JobPreview 1 (A9), Console 1 (A8) (counted by grep over `src/**/*.tsx`).
- Numbers are sans with `font-variant-numeric: tabular-nums`. Mono is for G-code and the console, the position readout and the live job timer only. `--font-mono: "SF Mono", "IBM Plex Mono", ui-monospace, monospace` with an `@font-face` for the bundled `public/fonts/IBMPlexMono-Regular.ttf` (present).
- A unit is never uppercased: caps labels carry the unit in a sentence-case `meta` span (`Positioning` + `10 mm step`).

### 3. A colour means one thing

Blue is interactive or selected (fills `--accent`, text `--accent-text`, filled primaries `--accent-strong`). Red is alarm, STOP and destructive. Amber is "needs attention". Green is machine ready or job done, not toggles. Tan is the KERF wordmark and Engrave in Preview only (pending D1). Layer colours mean layer identity, and no chrome reuses one (selection chrome becomes white). Components carry no state-colour literals; canvas-drawn colours live in one named constant per canvas component, because a 2D context cannot read CSS variables.

### 4. STOP presentation (Track A part only)

STOP is never drawn dimmed while it is enabled. Its `disabled={!machineConnected}` (JobActionBar.tsx:279) stays the single source of truth, and its style is derived from it plus existing state:
- **disabled** (`!machineConnected`): opacity 0.4, cursor not-allowed.
- **outline** (connected, no job, `machineState === "idle"`, not stale): transparent, 1px `--danger-text` border, `--danger-text` 13px/700, `flex: 1`, min-width 72px, height 32px.
- **solid** (connected and job running, or any non-idle state, or stale): `--danger-strong` fill, #fff 13px/700, `flex: 2`, min-width 120px, height 40px. Jog and home both store as `run` (machineStatus.ts:85-90) and an unknown state stores as `alarm` (:94), so this covers jogging, homing, hold, door, alarm, unknown and stale. A new connection starts stale (S3), so STOP is solid for the first status interval after connect; that is intended.
- While a job runs, START and FRAME shrink to `flex: 0 0 56px`; they stay rendered and disabled by their existing expressions. PAUSE keeps its size, label and behaviour.
- `handleStop`, its `onClick` and its `disabled` are byte-identical. Raising STOP above modals, a Stop key and stop-outcome reporting are TB1.

### 5. Say why, where the eye already is

Every disabled primary action whose reason Kerf already computes shows that reason as visible text beside it (11px, `--text-secondary`, a 6px `--warning` dot, `role="status"`), never only in a `title`. The `title` attributes stay (tests assert them). Status-message levels and lifetimes are TB8.

### 6. One dialog shell that owns no handlers

`ModalShell` is presentational. It renders the backdrop and the panel, calls `useFocusTrap(panelRef, open, initialFocus)` (the one door, `src/lib/hooks/useFocusTrap.ts`), and registers no keyboard listener.
- Props each migrated dialog passes with today's values: `backdropZIndex` and `panelZIndex` (9999/10000 for most, 2000/2000 for Material Test); `onBackdropClick` (exactly today's behaviour, or omitted); `initialFocus` (exactly today's ref, or omitted; NestingDialog passes `spacingFieldRef`); `onClose`, which only the close button uses and which is the function the dialog's Cancel already calls.
- Each dialog keeps its own `useEscapeClose` call, or its lack of one. Escape semantics, initial-focus changes and the Escape-deselect leak (ROADMAP Parking Lot, editing-shortcuts item 3) are TB9. Stacking order relative to STOP is TB1.
- **Initial focus does not move.** `useFocusTrap` focuses `initialFocus` if given, else the first focusable element in the panel (useFocusTrap.ts:56-63). A close button in the title row would become that element in every dialog that passes no `initialFocus`, so focus would open on a dismissing control. The shell therefore renders the close button **last in DOM order**, after the body and footer, absolutely positioned in the panel's top-right corner outside the scroll region. The first focusable element in the panel is then the dialog's own first control, exactly as today: none of the twelve migrated dialogs has a focusable element before its content at the base (checked per file; Settings opens on its width input, SettingsDialog.tsx:129). The one Tab-order change is the new close button as the last stop of the cycle, which Shift+Tab from the first control reaches. Defaulting `initialFocus` to the body's first control was rejected: it needs a change to `useFocusTrap`, which is in the scope deny-list. This is the shell's focus contract; TB9 owns it from A3's merge (see TB9).
- Look: widths 400, 480, 560 or 640 px (each dialog rounds up from today's width), or the current size rule for the two full-size previews (Dither, Power Curve); padding 20px; `max-height: calc(100vh - 48px)`; title 14px/600 with 16px below, padded right so the close button never covers it; a 24x24 close button with a 12px SVG glyph, `aria-label="Close"`, `--text-secondary`; the body scrolls (`overflow: auto; min-height: 0`); the footer sits outside the scroll region (flex-end, gap 8px, margin-top 20px); `--radius-lg`, `--shadow-modal`, 1px `--border`, `--bg-panel`; backdrop rgba(0,0,0,0.5).
- Buttons (`ModalButton`, exported from the same file): primary `--accent-strong` fill, #fff 13px/600, padding 6px 16px, `--radius-sm`, exactly one per dialog; secondary transparent with 1px `--border-control` and `--text-primary`; destructive transparent with `--danger-text`, hovering to `--danger-bg`. `ModalButton` and the close button bind their prop directly as the DOM handler (`onClick={onClick}`, `onClick={onClose}`, no wrapper), so a migrated button's handler receives exactly what it received before.
- `Banner` (created in A2) renders no ARIA role unless the caller passes one. Material Test's click refusal is the dialog's only `role="alert"` (MaterialTestDialog.tsx:642-657) and `machineJobLoop.test.tsx` reads it with `queryByRole("alert")`, which throws if a second alert appears.
- Not migrated: the ? sheet (the reference), the palette, the recovery prompt, onboarding, and GrblSettingsDialog. GRBL has no focus trap today and is allowlisted for that in `src/lib/__tests__/modalFocusContainment.test.tsx`; wrapping it in the shell would add a trap, which is a behaviour change, so A11 restyles its own markup to match and TB9 owns its modal contract.

### 7. Reachable and named, without new handlers

Hit areas are at least 24x24, made with padding plus negative margin so nothing shifts. Focus ring `2px solid var(--focus-ring)`, offset 2px; inputs, selects and textareas -1px; edge-to-edge section headers -3px. Icon-only controls get an `aria-label`, toggles get `aria-pressed`, labelled input groups get `role="group"` and `aria-labelledby`. Selection is never hue alone: selected options get weight 600 and a 2px blue edge (1px `--accent-border` plus `box-shadow: inset 0 0 0 1px var(--accent)`). Every new `useStore` selector returns a scalar or a stable reference, and derived arrays are computed outside the selector (CLAUDE.md, React error 185). Keyboard behaviour changes (Tab, menubar walking, Alt+T, reorder keys, initial focus) are TB9.

## Verification

**Track A changes no G-code.** That is a claim, so each batch proves it four ways, and any failure stops the batch:
1. **Scope.** `git diff --name-only <batch base>...HEAD` lists only the batch's files, and nothing under `src-tauri/`, `src/app/store/`, `src/lib/machine/` (A12's `machineStateDisplay.ts` strings excepted), `src/lib/fileOps/`, `src/lib/tools/`, `src/lib/geometry/`, `src/lib/hooks/`, `src/lib/shortcuts.ts`, `src/lib/fileDrop.ts`, `src/app/types.ts` or `src-tauri/tests/golden/`. A decision commit lists only its declared lines' file.
2. **Protected symbols.** Razor reads every hunk in the touched files and confirms that each protected symbol in the batch's list is byte-identical or moved verbatim, and that every `onClick`, `onChange`, `onKeyDown`, `onMouse*` and `disabled` attribute names the same function with the same arguments as at the base. A hunk inside a handler body, a store call, an import or trace call, a generation call, a default value or a gate expression is a stop.
   **Primitive equivalence.** Where a DOM control is replaced by a frozen primitive, the check moves from the DOM attribute to the prop, because the DOM handler becomes the primitive's own:
   - `ModalButton`, ModalShell's close button and a `Banner` action bind their prop directly as the DOM `onClick`. Equivalent when the prop is the function the replaced element's `onClick` named (or the same inline arrow, byte-identical), and the primitive's `disabled` is the old element's `disabled` expression.
   - `Segmented` calls `onChange(option.value)` on every click, the selected option included. Equivalent when, for each option, `onChange(option.value)` runs exactly the statements the old button's `onClick` ran: `onClick={() => setMode("text")}` becomes `onChange={setMode}` with `value: "text"`; an old handler that did more than call the setter is passed as an arrow whose body is that handler's body, byte-identical apart from the value becoming the arrow's parameter. Each option's `disabled` is the old button's expression.
   - Razor checks this per adoption, option by option, and records the old-to-new mapping in the review. That the primitives forward unchanged is proven once, in `segmented.test.tsx`, `modalShell.test.tsx` and `banner.test.tsx` (A2, A3), so Razor checks the prop, not the primitive's internals.
3. **Generation unchanged.** `npx vitest run` passes with no pre-existing test edited except the three named in the ledger (A3, A6, A12); that includes `src/lib/machine/__tests__` (gcodeGen, materialTestGcode, textGcode, canStartJob and the rest), which is where a TypeScript-built generation request would show a change. `cargo test` is not run per batch and is not counted as Track A evidence: rule 1 already proves nothing under `src-tauri/` changed, so the seventeen goldens cannot move, and a Rust build would cost time and disk (hand-off disk floor) to re-prove it.
