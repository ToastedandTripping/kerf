Three stress tests

Pre-mortem

1. Three months out, the operator opens a dialog during a jog or while controller status is stale and cannot activate STOP promptly. The raised stacking order exists only for the enumerated P8 states; centre hit-testing in injected run state passed. A focus trap or keyboard listener can also prevent access even when the button is painted on top. Type-specific worst case: motion strikes the frame or a powered beam continues on stationary stock, causing material damage, fire or injury. The plan should have required an uncertain-state/modal/input matrix and actual dispatch checks, followed by a bounded owner hardware check; software cannot certify beam extinction.
2. An Illustrator file imports at the wrong physical size or onto the wrong burn mode. The proposed CSS precedence disagrees with the artwork, mixed stroke/fill is unspecified, and a generator comment alone chooses 72 px/in for unitless data. Synthetic happy-path fixtures pass because they encode the chosen assumptions. The user burns an oversized or unexpectedly filled design. The warning was that “imports … at the size the file means” was promised without an authoritative fixture covering CSS cascade, viewBox/viewport dimensions and explicit unit overrides.
3. After a stop and reconnect, a delayed stop response repaints an old outcome; after an edit during generation, an older result appears current. The operator trusts a stale status or preview. Tests map outcomes independently and never reorder promises. Meanwhile batches advertised as independent require not-yet-created shared components, leading to duplicated primitives and unsafe integration fixes. The missing request identities and incorrect dependency graph were visible before implementation.

Load-bearing assumptions

- High confidence that the current handlers cannot remain byte-identical while implementing the specified result ownership: local JobActionBar reads result.endState only inside START, emits the old estimated-time message there, discards FRAME's stream result, and resets elapsed time when jobRunning becomes false. Resolve before implementation: specify where elapsed/progress/result are captured atomically, including STOP-driven termination, or P11 will report reset or incomplete values.
- Low confidence that z-index plus elementFromPoint establishes universal STOP access. It says nothing about modal focus, event propagation, future stacking contexts or omitted states. Resolve before implementation with the actual modal/shortcut harness; if wrong, the primary emergency UI is inaccessible precisely when needed.
- Low confidence that Illustrator provenance determines unit interpretation for all absent/unitless dimensions. The owner export check is pending and generator text is not a dimensional specification. Resolve before changing defaults with saved representative exports and expected dimensions; if unresolved, retain explicit user choice and visible dimensions rather than silently selecting a scaling heuristic.
- Low confidence that “presentation only” and unchanged Rust imply unchanged physical output. P21, P17–P20, P40–P41 and P69 alter inputs or execution context. Resolve before implementation by enumerating intended output deltas and testing all remaining invariants; otherwise unchanged goldens provide false reassurance.

Inversion

The rejected alternative of separating safety/behavior changes from visual polish wins if review controls cannot distinguish handler ordering, geometry, power settings and defaults from styling. Those conditions already hold: the plan simultaneously changes those inputs and demands byte-identical handlers. A shared or portal-based STOP surface wins over “One style change, no portal” if the existing modal structure cannot preserve both focus containment and emergency access; the plan has not tested that condition, so it cannot reject that implementation categorically. D3's Score alternative wins if the import/drawing intent is ambiguous and the owner prioritizes limiting accidental material damage; the plan itself describes Score as the cautious alternative and D3 remains unresolved, so Cut is not yet an authorized default.

Overall verdict: FAIL — blocked by multiple gating defects, especially incomplete STOP accessibility, impossible handler-preservation claims, incorrect import semantics, stale asynchronous outcomes and tests that cannot establish the stated safety guarantees. The plan has a written grill skip and names hardware checks, so those are not missing outright; the blockers are contradictions and missing acceptance conditions within the proposed work. Re-review after the author specifies executable controls and a consistent batch graph; do not treat this as permission to alter the frozen stop/pause transport or to reopen already waived release blockers.
