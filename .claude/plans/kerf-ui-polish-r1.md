## Intent

Polish here means the five-step loop the charter names (Import, Trace if raster, Assign to layers, Preview, Send) reads truthfully at every step. The operator can see what state the machine is in and why something is refused, can find the next action without hunting or scrolling, can tell a layer that will cut from one that won't, and can always find and read STOP. It also means one visual system in the house style (dark, minimal chrome, Apple-like restraint): one type scale, token-only colours, one dialog shell. The charter's first "done" condition rules out silent G-code errors, and most of the high items below are the screen-side version of that: a refusal shown only in a tooltip, a preview that isn't the job, an SVG outline that quietly becomes a filled engrave.

Grill: not run. The intent comes from Lee's request ("have a few UI critics run on opus extra high and come up with a plan for polishing") and the charter. The look-and-feel calls a grill would have surfaced are under Decisions for Lee.

**Out of scope.**
- New features (head-position marker, interface zoom, DXF mapping dialog and the rest under Deferrals) and anything CAD.
- Any change to safety logic: the stop path (`serial_stop`, `emergencyStop` ordering, DECISIONS 2026-09-20 and 2026-09-24), admission conditions in `canStartJob`, jog gating and motion trust (relay/kerf-safety-motion-trust, B4 pending), Pause (DECISIONS 2026-09-25: "A future session must not relabel, remove or re-wire Pause outside that plan"), the settings-write guards (S4a), power-scale verification (S4b), and G-code output (goldens stay byte-identical).

## Design principles

1. **Contrast floor.** Text is at least 4.5:1 on the background it actually sits on, and control borders are at least 3:1.
   - Tokens: `--text-primary #e8e8e8`, `--text-secondary #b3b3b3` (7.59:1 on #222), `--text-muted #949494` (5.24:1 on #222, 4.73:1 on #2a2a2a).
   - `--text-disabled #5c5c5c` is for genuinely disabled controls only.
   - `--border-control rgba(255,255,255,0.34)` (3.31:1 against the panel) is for inputs, selects and toggles. Dividers keep `--border`.
2. **One type scale.**
   - Tokens: `--text-2xs 10px` (caps section labels only), `--text-xs 11px` (the floor for every other string), `--text-sm 12px`, `--text-md 13px`, `--text-lg 14px`, `--text-xl 18px`. No 7, 8 or 9 px anywhere.
   - Values an operator reads from the bench (job timer, percent, machine state, position) are 12 px or larger. The job timer is 13px/600.
   - Numbers use sans with `font-variant-numeric: tabular-nums`. Mono is for G-code, the console, the position readout and the live job timer only.
   - Caps labels use `letter-spacing: 0.4px`, and a unit is never uppercased (mm stays mm).
3. **A colour means one thing, and only tokens carry it.**
   - Blue `--accent #4a90e2` means interactive or selected. Filled primaries use `--accent-strong #2b6cb0`, where white text is 5.42:1.
   - Red means alarm, STOP and destructive actions: `--danger-strong #c62828` for fills under white text (5.62:1), `--danger-text #f26b6b` for red text (5.37:1; `--danger` itself is only 4.02:1).
   - Amber `--warning #e2a74a` means "needs attention" but not an alarm.
   - Green `--success` means machine ready or job done, and nothing else (not toggles).
   - Tan `--accent-warm` is for the wordmark and Engrave in Preview only (pending D1).
   - Tints come from `-bg`/`-border` tokens. Components hold no state-colour hex or rgba literals.
   - Layer colours mean layer identity only, and no UI chrome reuses one.
4. **STOP is the strongest control whenever motion is possible.**
   - It is never drawn dimmed while it can act.
   - During a run it is at least 120x40 px: `#c62828` fill, `#fff` 13px/700 text.
   - No dialog can cover it (z-index 10001).
   - There is one stop handler. Every STOP button and key calls it.
5. **Say why, where the eye already is.**
   - Every disabled primary action shows its reason as visible text beside it (11px, `--text-secondary`, a 6px `--warning` dot), never only in a `title`.
   - Status messages carry a level. Error stays until replaced or clicked, warning lasts 8 s, info 3 s. Clicking any of them opens the Console.
6. **One dialog shell.** `ModalShell` specification:
   - Widths 400, 480, 560 or 640 px. Padding 20px.
   - Title 14px/600 with 16px below it. A 24x24 SVG close button on every dialog.
   - The body scrolls, and the footer sits outside the scroll region (flex-end, gap 8px, margin-top 20px).
   - Buttons are 13px with padding 6px 16px and `--radius-sm`. Each dialog has exactly one filled primary (`--accent-strong`), ghost secondaries (1px `--border-control`), and destructive actions as `--danger-text`.
   - `--radius-lg`, `--shadow-modal`, backdrop `rgba(0,0,0,0.5)`.
   - Focus trap and Escape are built in, and Escape uses `stopImmediatePropagation` so closing never also deselects (Parking Lot, editing-shortcuts item 3).
7. **Reachable and named.**
   - Hit areas are at least 24x24, made with padding plus negative margin so nothing shifts.
   - Focus ring: `2px solid var(--focus-ring)` with `--focus-ring #a8d0ff` (9.95:1 on #222), offset 2px. On inputs the offset is -1px, so the ring replaces the border edge instead of doubling it. On edge-to-edge section headers it is -3px.
   - Every icon-only control has an `aria-label`, and every toggle has `aria-pressed`.
   - Selection is never shown by hue alone: selected options get weight 600 plus `box-shadow: inset 0 0 0 2px currentColor`.
   - Every new `useStore` selector returns a scalar or a stable reference (CLAUDE.md, React error 185).

## Decisions for Lee

These are only look-and-feel and default calls. Everything technical above was decided under the 2026-09-29 delegation.

**D1. Should every button, slider and selected option use one colour?**
Today some primary buttons are tan and some are blue, and white text on the tan ones is hard to read (2.33:1).
Recommendation: blue for every action and selection, with tan kept only for the KERF name and the Engrave colour in Preview. The alternative keeps tan as the action colour with dark text on it (7.47:1).
It is easy to reverse (tokens), but it gates B7, B10 and B11.

**D2. Should the import and trace previews show your artwork on a light, paper-coloured panel (#f4f1ea)?**
Today black line art on the dark navy panel is nearly invisible (1.23:1).
Recommendation: yes, inside those preview boxes only. The rest of the app stays dark. The alternative is a mid-grey panel, which is less stark but still weak for thin lines.
Gates B5.

**D3. In a new project, which layer should drawn shapes and DXF files land on?**
Today it is Engrave, a fill layer, so an outline you draw or import burns as a filled block.
Recommendation: Cut, because an outline on a line layer traces the outline, which is what a drawn or DXF shape usually means. The cautious alternative is Score (30% power), where a mistake marks instead of cutting through.
Gates B7 (P41).

**D4. While the laser is moving, should the whole status bar at the bottom take a colour (blue running, amber paused or lid open, red alarm), with the state word in larger type?**
Today the state is a small word and a 6px dot.
Recommendation: yes, so you can read it from the bench. The alternative is larger text only.
Gates the tint part of K1, and the rest of K1 goes ahead without it.
