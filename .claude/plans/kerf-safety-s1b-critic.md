## Conditional dimensions

### X1. Physical & human safety — **CONCERN** [GATING]
**The brief's question 1, answered against the tree.** After the deletion no Rust code writes `$32`, and the buffered start refuses before any read or write unless the forwarded flag is true. The flag has one true-setter (`applyLaserModeReadback`, gated on `$32=1` in the readback and an unchanged settings generation), is cleared on every settings write (`send()` chokepoint, before and after the invoke), on a rejected readback (`connection.ts:787`), and on disconnect (`:411`), and is re-derived on every connect (`:209`). A stale stream after a reconnect is refused by admission (phase Idle at connect; a new job's epoch). So the remaining ways a buffered job can start on an unverified `$32=1` are: (1) the X5 window — a settings write whose invoke lands after the stream's invoke and wins the `command` lock first; it is admitted because `try_permit_begin(None)` checks phase only; reachable from the settings dialog and MachinePanel buttons, not the console; microseconds wide; S4a closes it; (2) a `0x18` between the readback and START on a controller whose reset does not preserve `$32` (assumption, core 3 i); (3) per-line mode, the default, which has no Rust check at all and rests on `canStartJob` until S4a. The plan states (1) and (3); it must state (2). **Worst case, named:** the flag is true, the controller is at `$32=0`, a buffered M4 job is admitted; at `$32=0` GRBL treats M4 as M3 and does not gate the spindle on motion, so the beam is at commanded power through every `G0` rapid. **Hardware-only:** none possible — buffered mode is reachable only by hand-setting localStorage and release builds carry no devtools; the plan flags it per the Testing SOP and ROADMAP `:5` already records buffered as not owner-tested. That is the honest answer, not a skipped step. Every failure path in the batch ends dark: refusal before I/O, missing key, and the post-refusal `emergencyStop` is a reset, which is the safe direction.

## Stress tests

### Pre-mortem — three months out, this failed
1. **The beam ran through rapids on a buffered job after a STOP.** The operator verified `$32=1`, ran a job, pressed STOP; the vendor controller's reset left `$32` at 0 (a fork behaviour, or a startup line the fork honours); the flag stayed true because nothing invalidates on `0x18`; the next buffered START was admitted and Rust trusted the flag. Should have seen: the parent's S4a lists "reset" as an invalidator and S1/S1b do not; one sentence in "What S1b does not satisfy" would have made the gap visible to whoever cut the interim build.
2. **T2 was "fixed" by weakening it.** The buffered pump read once more after the two acks, hit the exhausted script's EOF and returned `Disconnected`; the shortest edit was to drop `Ok("complete")` and keep the trace assertions; M1 still died, so the report said "all killed" and nobody noticed the control for a completing verified job was gone. Should have seen: `scripted_port.rs:348` returns `Ok(0)`, and `serial_pump.rs:185` maps it to `Disconnected`.
3. **The pilot went BASELINE_RED on a timeout and Ted ran cargo by hand to "warm" the directory.** A concurrent battery pushed the cold build past the pilot ceiling; the fix taken was a manual `cargo test` into the shared target dir, which the plan forbids. Should have seen: the plan's `pgrep -af mutation-battery` pre-check and E5's 14-minute figure; the 30-minute pilot ceiling covers it, but only if the contention note is read before launch.

### Load-bearing assumptions
1. **`grblLaserMode === true` means the controller reported `$32=1` on the current generation.** Verified in the merged S1 tree (three writers, one true-setter). High confidence; if wrong, Rust admits on a lie — which is exactly why S4a's native snapshot follows.
2. **`$32` survives `0x18` on the owner's controller.** Stock GRBL: yes (EEPROM). Vendor fork: unverified. Medium confidence; consequence is scenario 1. Resolve by stating it, not by testing it — the owner card cannot see the beam and the sim models stock.
3. **`drain_classified` never consumes a `Timeout` or `Hold` step.** Verified (`available_now` → `bytes_to_read`, which stops at those steps). High confidence; every re-script (O2, R6) and T1/T2 rest on it.
4. **A warning is not an error in the battery's cargo build.** Verified (no `deny`, no `[lints]`, no `RUSTFLAGS` in the test command). High confidence; if wrong, M2 and M4 would be false kills and the journal could not tell.

### Inversion — when would a rejected alternative win?
- **Native snapshot first (S4a), no TS flag forwarded.** Wins if the TS flag could not be made honest in TS. It was (S1, merged, verified). The ordering stands; S1b is the cheapest closure of N8 and of the write Lee refused, and S4a replaces the source without touching this check's shape.
- **Return the laser refusal with the `refused:` prefix so no stop follows.** Wins if a refusal that wrote nothing should never trigger a reset. Partly true — but `handleRefusal`'s contract ("the backend has already reset the controller or handed it to another admission") would then be false for this case, and a reset after a refused start is the safe direction. Keep the plan's choice; the Parking Lot line is the right home.
- **Keep O3 as a first-job-line ordering test rather than retiring it.** That is what the re-scripted O2 already is (O1's shape on the Phase A line, armed before spawn). Retiring O3 by name and proving O2 with M7 is the correct move; adding a duplicate would be gold-plating.
